# 照片查看器（带后端）

## 使用方式（本地）
1. 进入项目目录
2. 启动后端服务
3. 打开浏览器访问 `http://localhost:3000`
4. 点击「选择图片」上传图片
5. 页面会把图片以**网格**形式展示在当前页面
6. 点击缩略图可在弹窗中查看大图

## 重要说明（关于“上传”）
- 这个版本包含后端：图片会被保存到服务器的本地目录 `uploads/`。
- 你需要先启动后端，前端才可以通过 `/api/photos` 上传/读取图片。

## 启动后端
1. 安装依赖（首次需要）
   - `npm install`
2. 启动
   - `npm start`

默认端口为 `3000`（可用环境变量 `PORT` 改端口）。

## 后端接口（供前端使用）
- `GET /api/photos`：返回图片列表
- `POST /api/photos`：上传图片（表单字段名为 `photos`，支持一次上传多张）
- `DELETE /api/photos`：清空 `uploads/` 下的所有图片

## 常见问题
- 图片太大导致上传失败：请上传更小的图片，或减少一次选择的张数（后端单张默认限制 20MB）。

## 公网访问（任何人能打开）

思路：把本仓库部署到**支持 Node.js 的托管平台**，由平台分配一个 `https://你的域名` 对外提供服务。本项目的 `server.js` 同时提供静态页面和 API，**一个服务即可**，不需要再单独用 GitHub Pages。

### 1. 平台会做的事

- 平台会设置环境变量 `PORT`，本服务已读取 `process.env.PORT`。
- 服务已监听 `0.0.0.0`，适合在容器/云主机里对外暴露。

### 2. 上传文件持久化（重要）

很多云平台**每次发布会换容器**，若只把图片写在容器内磁盘，**重启或重新部署后上传可能丢失**。

- **推荐**：在平台上为应用挂载一块**持久磁盘**，并把环境变量 `UPLOAD_DIR` 指向该磁盘路径（例如 `/data/uploads`），让图片始终写在这块盘上。
- **长期方案**：把图片存对象存储（如 S3、阿里云 OSS），本仓库当前仍是「本地目录」方案。

### 3. 以 Render 为例（步骤概要）

1. 在 [Render](https://render.com) 新建 **Web Service**，连接你的 Git 仓库（或上传代码）。
2. **Build Command**：`npm install`
3. **Start Command**：`npm start`
4. **Health Check Path**：`/health`（可选，但建议填）
5. 在 **Environment** 里按需设置 `UPLOAD_DIR`（若你挂了持久磁盘，填磁盘上的目录）。
6. 部署完成后，用 Render 提供的 `https://xxx.onrender.com` 访问即可。

其他类似平台（Railway、Fly.io、国内云主机 + PM2 等）同理：**Node 启动命令 `npm start`**，并注意 `PORT` 与持久化目录。

### 4. 安全说明（公网开放上传时必读）

当前示例**没有登录、没有密码**，任何人若知道你的网址，理论上可以上传或调用清空接口。若仅个人相册可接受；若面向公网，建议后续增加：

- 上传前登录，或
- 为 `POST /api/photos`、`DELETE /api/photos` 增加密钥 / 管理口令（环境变量校验）

需要的话可以再帮你加一层「上传密钥」的简单保护。
